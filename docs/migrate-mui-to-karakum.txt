We are on branch `mlk/switch-mui-to-karakum`, created from `kw/master`.

Goal:
Migrate the MUI wrappers from the old v5/external-generator model to the in-repo Karakum model used by `kotlin-testing-library-react` and `kotlin-testing-library-user-event`, then upgrade the supported core MUI wrappers toward v7.3.9.

Important constraints:
- Do not rely on any supposed upstream PR/issue for this work. Earlier search results were stale/confusing.
- Do not use the external `mui-kotlin` repo as the main implementation path. The user explicitly wants the modern local Karakum pattern already used in this repo.
- MUI X packages should stay on their existing X line during this migration. Do not change `@mui/x-date-pickers` or `@mui/x-tree-view` just because core MUI is moving.

What we know:
- Existing MUI wrappers are old v5-era wrappers. Their READMEs say declarations were generated by external `mui-kotlin`, and the current source tree still reflects that.
- The correct local model is the sibling `karakum/` included-build pattern:
  - root `settings.gradle.kts` uses `includeKarakum("module")`
  - the generator subproject uses `generatorbuild.karakum-conventions`
  - generated output goes to `src/webMain/generated`
  - wrapper build logic picks that up automatically
- The testing-library wrappers are the reference implementation for this pattern:
  - `kotlin-testing-library-react`
  - `kotlin-testing-library-user-event`
- `@mui/material@7.3.9`, `@mui/system@7.3.9`, and `@mui/icons-material@7.3.9` exist and publish proper `exports`.
- The public type surface for `@mui/material@7.3.9` is rooted in:
  - `index.d.ts`
  - `*/index.d.ts`
  - special export `ButtonBase/TouchRipple.d.ts`
- The old generated MUI sources use v5-only deep imports and `mui.base` coupling.
- `kotlin-mui-material` currently depends on `kotlin-mui-base`, and the old generated sources reference `mui.base.*`.
- `kotlin-mui-base` is not part of the user’s desired v6/v7 upgrade set and is likely a removal target once regenerated wrappers no longer depend on it.

User-provided versioning boundary:
- Core packages that move through the MUI v6/v7 upgrade include:

Work already done:
- Added `includeKarakum("kotlin-mui-material")` to root settings.
- Added a prototype in-repo Karakum scaffold for `kotlin-mui-material`.
- Important discovery: `:kotlin-mui-material-karakum:build` only compiles the generator. The task that actually runs generation is:
  - `./gradlew :kotlin-mui-material-karakum:generateKarakumExternals`
- That task successfully generated a v7-shaped source tree under `kotlin-mui-material/src/webMain/generated`, which proves the Karakum wiring works.
- But the raw/default Karakum output is not usable yet:
  - root/module files were mostly commented re-exports
  - unresolved imports remained, including things like `React`, `@mui/types`, and `@mui/system`
- That experimental generated tree was deleted immediately so the existing wrapper build stays clean.
- After cleanup, this still passes:
  - `./gradlew :kotlin-mui-material:compileKotlinJs`

Current local changes:

- new `kotlin-mui-material/karakum/` scaffold
